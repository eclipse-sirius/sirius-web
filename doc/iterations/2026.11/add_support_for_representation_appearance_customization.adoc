= Add support for representation appearance customization

== Problem

The appearance of representations and their content is defined by representation descriptions.
Downstream applications cannot easily customize it without replacing the descriptions they want to customize.

== Key Result

* Application developers can customize the appearance of existing representations through server-side contributions, without replacing their representation descriptions.
* The customization mechanism must be applicable to different representation types.
The initial implementation will support background-color customization for diagram nodes.
* Style customizations from the _Appearance_ menu have a higher priority than style customizations registered in the server.

=== Acceptance Criteria

* An integration test should verify that a registered customization is applied to matching elements.
* An integration test should verify that a style property customized through the Appearance menu takes precedence over an applicable server-provided customization targeting the same property.

== Solution

One can register style customizations on the server via a backend extension point.
Registered customizations are automatically applied where applicable.
Each customization determines its applicability from the representation context, such as its description or editing context.
If several applicable customizations target the same property of the same element, only one will be used.

=== Scenarios

* **Scenario steps**
  * Sirius Web registers a server-side customization that sets the background color of class nodes to _green_ in Papaya class diagrams named “Overview”.
  * The end-user creates a Papaya class diagram and names it "Overview".
  * The class graphical nodes in that diagram have a green background.
  * The end-user creates a Papaya class diagram with another name.
  * The class graphical nodes in that diagram retain their original background color.

* **Scenario steps**
  * Sirius Web registers a server-side customization that sets the background color of class nodes to _green_ in Papaya class diagrams named “Overview”.
  * The end-user creates a Papaya class diagram and names it "Overview".
  * The class graphical nodes in that diagram have a green background.
  * The end user uses the _Appearance_ menu to set the background color of one class node to purple.
  * The background-color of the node is purple.

=== Cutting back

* **Nice-to-have:** Support for customizing all style properties beyond the background-color in a diagram.
* **Nice-to-have:** Allow users to select, from the project settings, which server-provided style customizations apply to their project.
The UI allows users to enable or disable each server-provided customization for their project.

== No-Gos

* Defining or editing style customizations at project scope is out of scope.
